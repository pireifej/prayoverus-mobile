SIGNED PRAY OVER US USER SESSION

The backend now issues a signed personal session after a successful login.

Successful login responses contain:
- Top-level: `user_session_token`
- Returned user object: `result[0].user_session_token`

After every successful email, Google, Facebook, or Apple login:
1. Read `user_session_token`.
2. Store it securely:
   - iOS: Keychain-backed secure storage
   - Android: Keystore-backed secure storage
3. Include it on protected backend requests using this exact header:
   `x-user-session-token: <user_session_token>`

Important:
- Do not put this token in the Authorization header.
- The Authorization header is already used for the app’s existing Basic API authentication.
- Protected requests therefore send both:
  - Existing `Authorization: Basic ...`
  - New `x-user-session-token: ...`
- Never log the user session token or provider OAuth credentials.
- Delete the session token when the user signs out.

Existing installed users will not have a session token yet. If a protected endpoint returns:
- HTTP 401
- `error: "USER_SESSION_REQUIRED"`

show a friendly “Please sign in again” message, clear stale authentication state, and take the user to login.

If the backend returns:
- HTTP 403
- `error: "USER_ID_MISMATCH"`

do not retry using another user ID. Clear the session and require a fresh login.

USER ID SECURITY

For protected calls, the backend now derives the user ID from the signed session.

The frontend should:
- Stop treating a body-supplied `userId` as authentication.
- Prefer omitting `userId` from protected requests if the endpoint does not otherwise need it.
- If an existing API payload still includes `userId`, it must exactly match the logged-in user.
- Never let cached data from one account remain after switching accounts.

SUBSCRIPTION UX

Free users:
- May post one prayer request per UTC day.
- Receive this response after reaching the limit:
  - HTTP 403
  - `error: "DAILY_LIMIT_REACHED"`
  - `message: "Free tier is limited to 1 request per day. Upgrade to Pro for unlimited requests."`
- Show an upgrade screen or purchase prompt when this occurs.
- Standard prayer generation remains available after authentication.
- Premium Daily Bread, archives, audio, prayer walks, detailed prayers, and extended prayers should show locked/upgrade UI.

Pro users:
- Unlimited prayer requests.
- Extended 250–350-word prayer generation.
- Full Daily Bread content and archives.
- Daily Bread audio.
- Detailed prayer content.
- Prayer audio and prayer-walk streaming.

Handle:
- HTTP 403 with `PRO_REQUIRED` by displaying the Pro upgrade screen.
- HTTP 503 from extended generation as a temporary retryable failure, not as a subscription failure.
- RevenueCat purchase cancellation without showing an error.
- Pending purchases appropriately on Android.
- Restored purchases by refreshing both RevenueCat customer information and `/api/subscriptions/pro-status`.
